過去，在 Windows 系統上運行 LINUX 套件需要仰賴 VM 或 Virtual Box，然而誠如前一章節所述，虛擬機安裝較為繁瑣，且存在效能過低的問題。在 2016 年，隨著 Windows 10週年更新，為了解決開發者在 Windows 和 Linux 之間切換環境的繁瑣，WSL1隨之問世。這一系統的設計初衷是將 Linux 命令行工具帶入 Windows，讓開發者可以直接使用 Bash shell 和其他常見的 Linux 工具，而無需安裝虛擬機或雙系統。這個變革性的計劃使得 Windows 成為一個更具吸引力的開發平台，讓 LINUX 套件在 WINDOWS 流暢運行有了新的路徑，相較於笨重的 VM，WSL1有著資源少(開機即用，幾乎不佔額外記憶體與 CPU)、速度快(Windows 與 Linux 檔案互通，專案程式碼存取效率高)、免設定(不需要開啟虛擬化平台設定)的多項優點。

然而 WSL1 最大的缺點即是沒有真正的 Linux 核心。它透過轉譯層把 Linux 系統呼叫變成 Windows API，這導致它在相容性、IO 效能以及進階工具支援上有嚴重的結構限制。其他缺點如不支援 Docker：無法原生執行需要真實核心或 cgroups 的容器與服務（如 MongoDB 有時會出問題）、跨系統磁碟效能差(在 Windows 檔案系統（/mnt/c）中讀寫大量小檔案時速度非常慢)、系統呼叫不完整(部分底層的 Linux 軟體、網路工具或高階應用因轉譯不完全而無法運行)、缺少原生核心功能(無法載入自訂的 Linux 核心模組或進行底層核心調校)，種種問題都讓 WSL1 遠遠無法滿足 LINUX 日常使用的標準。同時 VM 雖然也持續發展，但虛擬機笨重與計算效率過低等重要問題仍遲遲未見顯著的改善。並且隨著 Windows 系統的迭代，許多 VM 安裝流程也常因使用者電腦配置差異而出現不同的問題。

而後，一絲希望悄悄的萌芽，2019年五月 WSL2於 Build 開發者大會上首次亮相、同年 6 月向測試人員推出，並於 2020 年 5 月隨 Windows 10 2004 版正式向大眾發布，與 WSL 1不同， WSL2 最大的革新在於核心架構：WSL 1 使用轉譯層將 Linux 系統呼叫轉換為 Windows 呼叫；而 WSL 2 採用輕量型虛擬機器技術，並在裡面執行真正的 Linux 核心，提供完全相容的系統支援與極佳的檔案讀寫效能。WSL2 在 2020 年至 2021 年期間開始被大眾與開發者社群廣泛接受並主流化；而開源流體動力學軟體 OpenFOAM 確實是此技術的最大受益者之一。2021 年（主流化與爆發期）：微軟在 2021 年簡化了安裝流程（支援 wsl --install 一鍵安裝），並陸續加入 GPU 加速與 GUI 圖形介面支援。根據 Stack Overflow 年度開發者調查，WSL 的使用者佔比在此期間暴增，徹底擺脫了過去「Linux 玩具」的形象，成為開發者必備的生產力工具。

OpenFOAM 是一款原生為 Linux 設計的計算流體力學（CFD）軟體，在沒有 WSL2 之前，Windows 用戶的使用體驗非常痛苦。WSL2 的出現直接解決了三大歷史痛點：1. 檔案讀寫（I/O）效能暴增過去痛點：第一代 WSL1 採用指令轉換層，在讀寫 Windows 檔案系統（NTFS）時極其緩慢。OpenFOAM 在模擬時會產生海量的網格與時間步檔案，這使得 WSL1 幾乎無法用於大型計算。WSL2 的拯救：WSL2 採用了實際的 Linux ext4 檔案系統，I/O 效能提升了 2 到 20 倍。只要將 OpenFOAM 的工作目錄放在 Linux 的家目錄（如 ~/）下，計算速度就能直逼原生 Linux 系統。2. 徹底擺脫虛擬機與雙系統的繁瑣過去痛點：以前工程師必須安裝肥大的虛擬機（如 VirtualBox，極度耗費 CPU 和記憶體）或割硬碟做 Windows/Linux 雙系統。WSL2 的拯救：WSL2 屬於超輕量化的虛擬化技術，冷啟動只需不到 2 秒，且動態配置記憶體與 CPU 核心。這讓工程師能一邊用 Windows 的 CAD 軟體建模，一邊在旁邊的 WSL2 終端機直接執行 blockMesh 或 simpleFoam 進行計算。3. 官方原生編譯與後處理（ParaView）更便利過去痛點：過往有像是第三方編譯的 blueCFD-Core 試圖讓 OpenFOAM 跑在 Windows 上，但架構臃腫且版本更新往往落後官方。WSL2 的拯救：因為 WSL2 具備完整的系統呼叫相容性，用戶可以直接使用 OpenFOAM 官方提供的 Ubuntu 軟體源，用一行 apt-get 就能無痛安裝最新版。配合後來 WSL2 支援的 GUI 或是搭配 Windows 版的 ParaView，後處理視覺化（看流場圖）也變得流暢許多。

此一時期正是我開始執行關渡橋與龜山島計劃的練手時期，當時的我心力都放在計劃與熟悉 truchas 模式上，沒有考慮未來移植的可能性，也沒有其他使用 WSL2 的需求。而如今，AI 發展盛行的2026年，WSL2 技術日臻成熟，並且可透過 LXD 容器或 DOCKER 來打包舊時代程序所依賴的環境套件，兩者的差異主要在打包的體量上，LXD 容器打包的是整個 LINUX 環境，就像是一個輕裝版的 VM，而 DOCKER 打包的主要是程式本身及其所適配的套件，簡而言之，LXD 提供的是一個類似舊版機台的環境，它可以完美地融入 WSL2中，在享有 WSL2的新穎環境的同時高速運行，並享有以下好處：
1. 超低資源消耗：LXD 使用作業系統級虛擬化（容器）。它比在 WSL2 裡跑 KVM 或 VirtualBox 等傳統虛擬機（VM）更省記憶體與 CPU。
2. 完整系統體驗：不同於 Docker 專注於單一應用（Application Container），LXD 提供完整的系統容器（System Container）。每個容器都有獨立的 init 系統（如 systemd），運作起來就像一台獨立的 Linux 虛擬機。
3. 秒級啟動速度：LXD 容器可在幾秒內啟動完畢，遠快於傳統虛擬機的開機時間。原生網路與 IP：LXD 容器擁有獨立的橋接網路，能輕易獲取獨立的 IP 位址，方便進行網頁伺服器、資料庫等網路服務的測試。
4. 快照與克隆：支援極速建立系統快照（Snapshot）與複製（Clone）。非常適合用來做實驗，弄壞了可以一鍵還原。完美的沙盒隔離：你可以在 WSL2 中建立多個獨立的 Linux 環境（如 Ubuntu、Debian、CentOS），彼此完全隔離，不會弄髒你的主 WSL2 環境。
  
 這一切似乎都隨著我的研究步伐，在我最需要的時候、以最契合的方式、在最適當的時機出現。

無人在意的角落裡，LANL truchas 團隊其實也於 Github 上默默推出適用於 WSL2 的版本，但其安裝步驟仍較為繁瑣，並且在操作習慣(inp 檔設置、運行命令)與程式碼(source code)上，皆與實驗室慣用的版本相去甚遠，因此幾經嘗試後，我並沒有選擇以該版本 truchas 作為實驗室程式的移植載體。

過去在實驗室機台進行模擬，需要由管理員在主機台開設個人帳號，完成後會有一個自己專屬的 LINUX 系統來安裝 Truchas, 常用軟體如 GMV, Tecplot, MATLAB 等，學生會在機台上進行編譯、模擬及繪圖，隨著時代發展，MATLAB、Tecplot 等軟體也隨著 Windows 版本推進而持續更新，為了獲得新版本的使用效能，流程改為將模擬檔案下載至 Windows 系統的個人電腦，修改程式碼亦多在 Windows 系統上進行，然而這套流程其實有許多隱患，首先就是移動檔案，若檔案容量過大常常耗費時間在等待檔案傳輸；其次是換行符號問題，Windows 介面編輯程式碼時，常常會因為 Windows 換行符號 (CRLF = `\r\n`) 與 Linux 換行符號 (LF = `\n` ) 的不相容，導致 Linux 系統或模擬軟體（如 Truchas）在解析檔案時出錯，進而拋出 `\r: command not found` 或解析失敗等隱形 Bug；而最後也是最根源的問題就是機台環境過時，更新機台的 LINUX 環境並不困難，但由於 Truchas 編譯所依賴的平行運算套件與編譯套件版本過舊(如 PGSLib、Chaco、Ubiksolve、GCC ...），因此機台環境被迫限制在能兼容上述套件的環境．並且部分編譯邏輯被寫定在文件深處，因此可謂牽一髮而動全身，無論從技術層面或實際效益而言，將各套件升級至新版本絕不是合適的方案，再退一萬步說，即使真的成功升級，二十年後隨著 Windows 版本迭代又會面臨相同的問題。因此，合理的解決方案只有兩個，一是完全轉換成 Windows 版本，但這會面臨前面說的編譯邏輯修復問題，更重要的是舊版 Truchas 依賴的平行運算庫（如 MPI）在 Windows 下存在嚴重的執行緒排程效能衰退，且舊時代後處理工具（如 GMV）高度依賴 Linux 的 POSIX 與 X11 圖形渲染管線，在 Windows 環境下缺乏原生支援，會導致圖形化介面完全無法啟動，再加上強行 Windows 化將使專案完全脫離主流科學計算的 Linux 開源生態系（導致未來難以整合如 Gmsh 網格生成、ParaView 巨量資料視覺化、OpenFOAM 流體力學模擬等 Linux 原生工程軟體，且無法直接串接 PETSc 等高效能平行代數求解器，使專案淪為無法引進開源社群資源與工業標準的技術孤島），最後剩下的方案只有一個，打包到 WSL2 上！
